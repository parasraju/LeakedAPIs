Overview

API Instructor continuously searches GitHub code, issues, and commits for leaked keys across 24 services. Each hit is entropy-filtered, context-checked, Bloom-deduped, and live-validated.

ParamDefaultDescription

Scanning

  1. Enter github_pat_... (public repos read-only)
  2. Set Pages 10, Start 1 for fresh scan
  3. Click Start Scan — progress updates via /api/scan/status every 3s
  4. Rate limit 30 req/min auto-handled via token bucket
Early-stop after 3 empty pages saves ~40% API calls.

Security

  • Tokens never logged, never in URL — masked ••••••••
  • Keys masked sk_test_•••••••••••• in table, modal, logs
  • Cleared invalids added to blocked_keys — never reappear
  • Entropy >2.5 + keyword context window 40 chars reduces false positives

API Reference

GET /api/stats— totals, valid/invalid, services
GET /api/keys?limit=500— masked keys
POST /api/scan/start— {tokens, pages, start_page}

FAQ

Why invalid jumps 10→100?

Normal — GitHub has many revoked keys. Valid stays 0-5, invalid climbs fast. Clear after scan stops.

Failed to fetch on Clear?

Stop scan first — Clear is 409 while scanning. DB is WAL + blocked_keys persistent.
